# Multi-Target Containers for Quarto, Shiny, and Bayesian HPC Workflows

## Why Multi-Target Container Compilation Matters

Modern R projects span diverse deployment targets:

- **Reproducible Quarto manuscripts** combining R, Python
  (`reticulate`/Jupyter), LaTeX PDF output, and spatial or graphics
  libraries (`sf`, `ragg`).
- **Production Shiny applications** requiring non-root containers, HTTP
  health checks, background async workers (`mirai`/`promises`), and a
  reverse proxy.
- **HPC Bayesian & compiled pipelines** (`cmdstanr`, `RTMB`, `rjags`,
  `Rcpp`, `rextendr`) where university clusters run **Apptainer /
  Singularity** rather than rootful Docker.

`rcapsule` compiles all three targets from a single static project scan
and verifies every emitted specification against its built-in security
and reproducibility linter.

## 2. Production Shiny + Async Worker + Reverse Proxy Stack

When
[`scan_project()`](https://marcusharrisphd.com/rcapsule/reference/scan_project.md)
detects a Shiny application (`app.R` or `ui.R`/`server.R`) alongside
async workers (`worker.R`, `mirai`, `promises`),
[`compile_compose()`](https://marcusharrisphd.com/rcapsule/reference/compile_compose.md)
generates a hardened three-service stack (`app`, `worker`, and a pinned
`caddy:2.8.4-alpine` reverse proxy) with `no-new-privileges`, health
checks, and resource limits:

``` r

s_dir <- tempfile("rcapsule_shiny_demo_")
dir.create(s_dir)

writeLines(
  c(
    "library(shiny)",
    "library(bslib)",
    "library(mirai)",
    "ui <- page_sidebar(title = 'Forecast Dashboard', sidebar = sidebar('Inputs'), 'Plot')",
    "server <- function(input, output, session) {}",
    "shinyApp(ui, server)"
  ),
  file.path(s_dir, "app.R")
)
writeLines("library(mirai)\ndaemons(2)", file.path(s_dir, "worker.R"))

sc_s <- scan_project(s_dir)
comp_s <- compile_compose(sc_s, port = 3838L, proxy_port = 8080L)
lint_container_spec(comp_s)
```

## 3. Bayesian & Compiled HPC Recipe for Apptainer

On university HPC clusters where Docker is unavailable,
[`compile_apptainer()`](https://marcusharrisphd.com/rcapsule/reference/compile_apptainer.md)
produces an Apptainer `.def` recipe complete with `Bootstrap: docker`,
pinned base tags, `set -euo pipefail`, HPC bind directories (`/scratch`,
`/work`, `/data`), non-root read permissions, `%runscript`, and `%test`:

``` r

h_dir <- tempfile("rcapsule_hpc_demo_")
dir.create(file.path(h_dir, "src"), recursive = TRUE)

writeLines(
  c(
    "library(cmdstanr)",
    "library(RTMB)",
    "library(Rcpp)",
    "m <- cmdstanr::cmdstan_model('model.stan')"
  ),
  file.path(h_dir, "run.R")
)
writeLines("parameters { real mu; } model { mu ~ normal(0, 1); }", file.path(h_dir, "model.stan"))
writeLines("#include <Rcpp.h>", file.path(h_dir, "src", "kernel.cpp"))

sc_h <- scan_project(h_dir)
def_h <- compile_apptainer(sc_h, r_version = "4.4.1")
lint_container_spec(def_h)
```

## 4. Static Auditing of Hand-Written Container Specs

[`lint_container_spec()`](https://marcusharrisphd.com/rcapsule/reference/lint_container_spec.md)
can also audit existing hand-written Dockerfiles, Compose files, or
Apptainer definitions to catch reproducibility and security pitfalls
before deployment:

``` r

problematic_dockerfile <- c(
  "FROM rocker/r-ver:latest",
  "ENV API_KEY=hardcoded_token_value",
  "RUN apt-get update && apt-get install -y libgdal-dev",
  "COPY . /app",
  "RUN Rscript -e \"renv::restore()\""
)

lint_container_spec(problematic_dockerfile, type = "dockerfile")
#> 
#> ── rcapsule Container Lint (dockerfile): FAIL ──────────────────────────────────
#> Errors: 2 | Warnings: 4 | Info: 2
#> ✖ [DF001] (line 1) Base image 'rocker/r-ver:latest' uses mutable ':latest' tag.
#> ! [DF008] (line 2) Potential hardcoded secret detected in ENV instruction.
#> ! [DF002] (line 3) apt-get install without cleaning /var/lib/apt/lists/* bloats image layers.
#> ! [DF003] (line 3) apt-get install missing '--no-install-recommends'.
#> ! [DF007] (line 4) Copying full project context before renv::restore() busts Docker build cache on every edit.
#> ✖ [DF004] (line 1) Final stage has no non-root USER instruction; container runs as root.
#> ℹ [DF005] (line 1) No HEALTHCHECK instruction in final stage.
#> ℹ [DF009] (line 1) No WORKDIR instruction in final stage.
```
